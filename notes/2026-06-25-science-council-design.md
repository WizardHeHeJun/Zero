# 跨学科科学家议会：开发期评审委员会（设计）

> **日期**：2026-06-25
> **性质**：设计（非实现）。把「为项目创建对应学科的科学家 agent、在算法内容上跨学科讨论」落成可运行机制。
> **决策**（2026-06-25 与用户确认 + 后续澄清）：科学家议会**只为"创建/构建项目"服务**——以**项目结果/输出为分析起点**，做开发期的跨学科评审与设计，**绝不介入项目内数据（情绪/记忆/语言）的产生**。故只保留**开发期评审委员会**（harness 层）；先前"两者结合"里设想的运行期介入层**已撤除**（见 §三）。本轮**先出详细设计**，过一遍再脚手架实体。
> **缘起**：项目融合数学/心理学/生物学/神经科学/计算科学五学科，且有硬要求「所有学术内容须有学术材料支撑」。本机制把这条要求从"靠人自觉"变成"靠一组带学科视角、强制引文献的 agent 评审"，让跨学科融合可争论、可追溯。

---

## 一、治理原则（最高约束，先钉死）

科学家议会**只为"创建/构建这个项目"服务**，它是开发工具，**不是产品的一部分**：

1. **结果优先**：议会**以项目的结果/输出为分析起点**——情绪轨迹、生成的语言、记忆/经历内容、测试与 eval 数据——据此做跨学科评审与设计判断。
2. **不介入数据产生**：议会**绝不**参与或改写项目内数据的产生。数字人的情绪由确定性引擎（`affect_math`）按设计自行生成、记忆由记忆层按规则写入、语言由语言层生成——这些**不被议会触碰、不被委员会"决议"污染**。
3. **开发期顾问**：议会在开发/设计/选型时被唤起，产出带引文的设计决策与批评；不随产品运行。

**为什么**：把分析者与被分析的系统分开，避免污染与循环论证——若让"科学家委员会"下场参与生成情绪/记忆，产出的就不再是引擎的真实结果，而是被外部干预的结果，项目结论失真。这同时与核心红线一致（确定性热路径、记忆节流、torch/LLM 隔离）。

> **误区警告**：议会**不是**"一群科学家投票决定数字人此刻该感到什么/该说什么"。情绪是确定性贝叶斯引擎（`affect_math`）的职责（torch/LLM-free、`rng_seed` 可复现、零回归）；语言是语言层的职责。议会只在**开发期**、**从结果出发**评审这些机制建得对不对，**绝不下场生成**。

## 二、开发期评审委员会（本机制的全部）

### 2.1 席位与职责

| 席位 | 学科视角 / 把关的算法 | 文献锚（agent 须 WebSearch 现场核验，不凭记忆） |
| --- | --- | --- |
| **数学家** | 贝叶斯推断 / 动力系统 / 优化：`gaussian_fuse`·`fuse_terms`·`mood_step` 分岔·`precision_reconcile`·主动推断/自由能 | Friston 自由能；Gottman 双稳方程；Kalman 融合 |
| **心理学家** | 评价理论（OCC / Scherer CPM）·情绪调节（Gross）·人格（大五/PAD）·环状模型 | Russell 环状；Scherer CPM；Gross 过程模型；Mehrabian PAD |
| **生物 / 生理学家** | 神经环路 · 自主神经（HRV/EDA）· 面部肌肉（FACS）· 内分泌 | Ekman & Friesen FACS；LeDoux 生存回路；McGaugh 情绪记忆调制 |
| **神经科学家** | 预测编码 · 全局工作空间 · 显著网络 · 杏仁核多通路 · DA-RPE | Dehaene GNW；Menon 三网络；Pessoa many-roads；Barrett 建构论 |
| **计算机科学家** | 多 Agent 编排 · 软件架构 · **项目红线** · 可行性 · 耦合/成本 | 本仓 `.claude/rules/`；工程现实约束 |
| **主持 / 综合者** | 路由相关专家、暴露跨学科张力、收敛成带引文的决策（Supervisor 式） | — |

**CS 席的特殊作用**：它是红线守门人——任何"学术上更忠实但工程上违红线/不可行"的建议，由它标 BLOCK，使议会产出始终落得了地（不空谈）；任何"下场生成/介入数据产生"的提议也由它直接 BLOCK（守 §一）。

### 2.2 评审协议（三相）

议会的**输入**：一个设计问题/算法提案，**或对项目某次结果/输出的分析**（轨迹、transcript、记忆内容、eval 数据）。**输出**：带引文的设计决策与批评，落 `notes/`/PRP。

```text
输入（算法/设计问题，或对项目结果的分析）
  └─ 主持路由 → 仅相关席位（非每次全员，省成本）
       ├─ 相 1 独立评审：每席各出 {判定 + 引用 + 修正}
       ├─ 相 2 交叉质询：学科冲突处互相回应（主持暴露张力）
       └─ 相 3 综合：主持收敛 → 设计决策（含"故意简化及其代价"）→ 落 notes/PRP
```

- **相 1**：每席给结构化判定（见 2.3），**必须 ≥1 条现场核验的一手文献**（强制执行"学术须有支撑"）。
- **相 2**：暴露真实张力——例如神经科学席的「Barrett 简并、无情绪指纹」vs 工程席想要的「离散通道」（这条张力 notes 里已有），由主持摆上台面而非和稀泥。
- **相 3**：主持产出决策：**建什么 / 哪些是可接受的刻意简化（给理由）/ 哪些失真必须改 / 哪些悬而未决**，连同引文写进 `notes/` 或 PRP 的 `design.md`。

### 2.3 输出格式（仿 `code-reviewer` 的分级，但按学科）

每席一条：
- **判定**：`忠实` / `简化`（可接受的抽象，注明丢了什么）/ `失真`（错误，须改，相当于 BLOCK）
- **引用**：作者-年份-出处（现场 WebSearch 核验，给链接）
- **修正建议**：具体到函数/常量/结构（落 `file:line` 级）

主持综合：一段决策 + 一张"各席判定汇总表" + 落库指针。

### 2.4 harness 落点

- `.claude/agents/`：6 个定义（`scientist-math` / `scientist-psych` / `scientist-bio` / `scientist-neuro` / `scientist-cs` / `science-moderator`）。每个 = 聚焦的系统提示（学科视角 + 必引文献 + 输出 schema + **advisory-only**）。
- **工具集**：`Read/Glob/Grep`（看代码与项目结果）+ `WebSearch/WebFetch`（核验文献）；**不给 `Edit/Write`**——议会是顾问，不直接改代码、更不下场生成数据（与 `code-reviewer` 同款只读）。
- **入口**：`/science-council <提案/结果>` skill 编排 fan-out + 综合；或在 PRP 的 `generate-prp/validate-prp` 设计阶段加一道「跨学科评审」门。
- **产出汇入**：`notes/` 设计决策 / PRP `design.md`，带引文——与项目既有的"每个 notes 固化 WebSearch 文献"惯例同源。

### 2.5 护栏（为什么不破坏项目）

- **只读顾问**：不写 `src/`，不进运行时回路，不参与数据产生（§一治理原则）。
- **强制引文**：agent 提示里写死"凭记忆引用 = 无效，必须 WebSearch 核验"（对齐用户硬要求与既有惯例）。
- **CS 席守红线**：议会建议不可能绕过三层依赖/确定性热路径/记忆节流等红线，也不可能把自己接进生成回路。
- **按需路由**：trivial/bugfix/重命名不开议会；只在"新算法/设计选型/学术忠实性存疑/分析某次结果"时开（控成本）。

## 三、明确排除：运行期不介入数据产生

先前"两者结合"曾设想一个运行期"元认知/议事层"——**现按用户澄清撤除**：任何让议会在产品运行时参与推理/表达/情绪/记忆生成的形态，都属于"介入项目内数据的产生"，违反 §一治理原则，**不做**。

- 数字人运行时的情绪/记忆/语言，**只**由项目自身的引擎/记忆层/语言层按既有设计生成；议会不在这条回路里。
- 议会需要的"运行时信息"一律是**事后读取的结果/输出**（轨迹、transcript、记忆内容、eval），仅用于开发期分析——**只读、离线、零反馈**，不构成对生成的干预。
- 若将来确需产品级"自我解释/深思"特性，那是**产品功能**（走语言层、单独立项、仍不得污染确定性引擎），与本"开发期议会"是两回事，不在本设计内混谈。

## 四、与现有架构/工作流的对接

- **复用模式**：`code-reviewer`（只读顾问 subagent）+ Supervisor（主持=综合者）+ PRP 四阶段（评审做设计门）。
- **喂养知识层**：议会决策落 `notes/`/PRP，再按需同步进 `ai-docs` 模块 guide——延续"代码改了文档跟上"的链路。
- **可选 bootstrap**：席位 persona 可用 `huashu-nuwa`/`create-colleague` 蒸馏起草，但建议**手写**系统提示以精确控制"学科视角 + 强制引文 + 只读 + 不下场生成"。

## 五、风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 成本（每提案拉 5–6 个 subagent） | 主持按相关性路由，非全员；trivial 改动不开议会 |
| 引用造假（LLM 凭记忆编文献） | agent 提示强制"WebSearch 现场核验 + 给链接"，未核验判无效（项目硬要求 + 已有惯例） |
| persona 流于表面 | 每席系统提示锚定具体文献与本仓具体函数/常量，输出须落到 `file:line` 级 |
| 议会被误接进生成回路 | advisory-only + 只读项目结果 + CS 席守红线；任何"下场生成/介入数据产生"的提议直接 BLOCK（§一） |
